# Kubernetes deployment

Kustomize layout:

```
k8s/
├── base/                  Deployment, Service, ConfigMap, PVC, HPA, PDB (namespace: dragon)
└── overlays/
    ├── staging/           1 replica, staging DB/SSM URLs
    └── production/        3+ replicas, larger resources (profile "prod"; see note in the overlay)
```

## First-time setup

The secret is not part of the manifests. Create it once per namespace
(`base/secret.example.yaml` lists the keys):

```bash
kubectl -n dragon create secret generic card-service-secrets \
  --from-literal=CARD_DATASOURCE_PASSWORD=... \
  --from-literal=SPRING_DATA_REDIS_PASSWORD=... \
  --from-literal=VAULT_TOKEN=... \
  --from-literal=SSM_DECRYPT_KEY=... \
  --from-literal=UAA_CLIENT_CLIENT_SECRET=...
```

The uploads volume (`card-service-uploads`) needs a `ReadWriteMany` storage class,
because a file generated by one pod can be downloaded through another.

## Deploy

```bash
kubectl kustomize k8s/overlays/staging          # preview
kubectl apply -k k8s/overlays/staging
kubectl -n dragon rollout status deployment/card-service
```

To deploy a specific image tag, change `newTag` in the overlay
(or `kustomize edit set image card-service=registry.bmicc.ir/library/cardservice:<tag>`).

## Configuration

All settings come from environment variables (ConfigMap + Secret), which override the
`application*.yml/properties` files. Probes use `/actuator/health/liveness` and
`/actuator/health/readiness`; only `health` and `info` actuator endpoints are exposed.
